# IAM policies and security configuration

## Principles

1. **No long-lived credentials anywhere.** GitHub uses OIDC. Lambda and ECS use IAM roles. Apps
   authenticate to the database with 15-minute IAM tokens.
2. **Least privilege per workload.** Every Lambda has its own role, and the ECS task role is separate
   from the execution role.
3. **Network isolation by tier.** Security groups only reference other security groups, never CIDR
   ranges (except outbound HTTPS to AWS APIs).
4. **Defence in depth.** The private server is protected by the network (internal ALB, SGs) *and* by
   application auth (a shared token).

## IAM roles

| Role | Assumed by | Permissions | Scope |
|---|---|---|---|
| `graphql-app-github-deploy` | GitHub Actions via OIDC | Deploy the project's services; manage only `graphql-app-*` IAM roles | Trust: this repo only, `main` branch or `production` environment. Region-locked. Cannot modify itself. |
| `graphql-app-lambdas-prod-queries-*` | `queries` Lambda | `rds-db:connect`, VPC ENI management, logs, X-Ray | The DB user on **this proxy** only |
| `graphql-app-lambdas-prod-mutations-*` | `mutations` Lambda | `secretsmanager:GetSecretValue`, VPC, logs, X-Ray | The **internal token** secret ARN only |
| `graphql-app-lambdas-prod-subscriptions-*` | `subscriptions` Lambda | logs, X-Ray | Nothing else |
| `graphql-app-lambdas-prod-migrate-*` | `migrate` Lambda | `rds-db:connect`, VPC, logs, X-Ray | Same as queries |
| `graphql-app-prod-ecs-execution` | ECS agent | Pull from ECR, write logs, read **one** secret | Used only at task start |
| `graphql-app-prod-ecs-task` | Application code in the container | `rds-db:connect` | The DB user on this proxy only |
| `graphql-app-prod-rds-proxy` | RDS Proxy | `secretsmanager:GetSecretValue` | The RDS-managed master secret only |
| `graphql-app-prod-rds-monitoring` | RDS enhanced monitoring | AWS managed policy | — |
| `graphql-app-prod-vpc-flow-logs` | VPC Flow Logs | Write to one log group | — |
| AppSync data source roles (auto-generated) | AppSync | `lambda:InvokeFunction` | Each resolver Lambda only |

### Example: `queries` Lambda policy (generated from `serverless.yml`)

```json
{
  "Effect": "Allow",
  "Action": "rds-db:connect",
  "Resource": "arn:aws:rds-db:us-east-1:<account>:dbuser:prx-0abc123def456/app_admin"
}
```

### GitHub OIDC trust policy (`infrastructure/bootstrap/main.tf`)

```json
"Condition": {
  "StringEquals": { "token.actions.githubusercontent.com:aud": "sts.amazonaws.com" },
  "StringLike": {
    "token.actions.githubusercontent.com:sub": [
      "repo:Md-Adheep/graphql-serverless-aws:ref:refs/heads/main",
      "repo:Md-Adheep/graphql-serverless-aws:environment:production"
    ]
  }
}
```

Pull requests and forks **cannot** assume the role. CI on PRs needs no AWS access.

The deploy policy includes an explicit `Deny iam:*` on the deploy role itself, so a compromised
workflow can't escalate its own permissions. `iam:CreateRole` and `iam:PassRole` are limited to
`role/graphql-app-*`.

## Secrets and sensitive data

| Secret | Stored in | Who can read it | How it reaches the workload |
|---|---|---|---|
| RDS master password | Secrets Manager, **created and rotated by RDS** (`manage_master_user_password`) | RDS Proxy role only | Never reaches the app. The proxy uses it to pool connections. |
| DB auth for apps | — (IAM token) | Lambda/ECS roles with `rds-db:connect` | `@aws-sdk/rds-signer` creates a 15-minute token per connection |
| Internal API token (Lambda → Fargate) | Secrets Manager (random 48 chars, generated by Terraform) | `mutations` Lambda role and ECS execution role | Lambda: read at runtime and cached for 5 minutes. ECS: injected as an env var at task start through the task definition `secrets` block. |
| AWS credentials for CI | — (OIDC) | GitHub workflows on `main` / `production` | `aws-actions/configure-aws-credentials` → STS (1-hour session) |
| Alert email | GitHub **secret** `ALERT_EMAIL` | Deploy workflow | `TF_VAR_alert_email` |
| AppSync API key | AppSync | Public by design (it's in the JS bundle) | Injected at frontend build time from the deployed API. Used for identification and throttling, **not** authorisation of sensitive data. |

**What is never committed:** `.env*` (except `.env.example`), `*.tfvars`, `*.tfstate` (`.gitignore`).
The Terraform state holds the internal token, so it lives in an encrypted, versioned, private,
TLS-only S3 bucket.

**What CI/CD passes between steps:** only non-secret identifiers (ARNs, IDs, endpoints) through
SSM Parameter Store. Secret *values* are never written to SSM, GitHub outputs or logs.

## Network security

```
Internet ──▶ CloudFront ──▶ S3            (bucket private, OAC-signed requests only)
Internet ──▶ AppSync                       (managed, API key)
             AppSync ──▶ Lambda (VPC)
Lambda SG    ──80──▶   ALB SG  (internal)  ──4000──▶ ECS SG
Lambda SG    ──5432──▶ Proxy SG ◀──5432── ECS SG
Proxy SG     ──5432──▶ RDS SG
```

| Control | Where |
|---|---|
| RDS `publicly_accessible = false`, database subnets with **no route** to NAT or IGW | `modules/rds`, `modules/vpc` |
| RDS accepts connections **only from the proxy SG**. Apps can't bypass the proxy. | `environments/prod/security.tf` |
| TLS required: `rds.force_ssl = 1` and proxy `require_tls = true`. Clients verify certificates (`rejectUnauthorized: true`). | `modules/rds`, `db.ts` |
| Storage encryption at rest (RDS, S3, ECR, Secrets Manager) | all modules |
| Internal ALB has **no** internet-facing listener. `drop_invalid_header_fields = true`. Unknown paths return 404. | `modules/ecs` |
| Private server: constant-time token check, 100 KB body limit, introspection off in prod, internal errors masked | `graphql-server/src` |
| Containers run as non-root `node` with a read-only root filesystem | `Dockerfile`, task definition |
| ECR scan on push, immutable tags | `modules/ecs` |
| Default VPC security group stripped of all rules (CIS 5.4) | `modules/vpc` |
| VPC Flow Logs (rejected traffic) → CloudWatch | `modules/vpc` |
| CloudFront: HTTPS redirect, HSTS (2 years, preload), CSP, `X-Frame-Options: DENY`, `nosniff`, strict referrer | `modules/frontend` |
| S3 bucket policies deny non-TLS requests | `modules/frontend`, `bootstrap` |
| Input validation in both the Lambdas and the server (UUIDs, enum, lengths). All SQL is parameterised. | `validation.ts` |
| Dependency scanning: `npm audit` in CI, Dependabot for npm, Docker, Terraform and Actions | `ci.yml`, `dependabot.yml` |

## Production hardening (out of scope for the demo)

- **User auth:** switch AppSync to Amazon Cognito user pools (`@aws_cognito_user_pools`) for
  per-user authorisation. Keep the API key only for public reads.
- **AWS WAF** on CloudFront and AppSync (rate limiting, managed rule groups). About $5+/month per web ACL.
- **TLS on the internal ALB** with a private ACM certificate and a Route 53 private hosted zone.
- **Separate DB users:** an app role with only `SELECT/INSERT/UPDATE/DELETE` on `tasks` instead of the master user.
- **Customer-managed KMS keys** for Secrets Manager, RDS and logs, with key-policy separation.
- **Separate plan and apply roles**, so PRs can run `terraform plan` with read-only access.
